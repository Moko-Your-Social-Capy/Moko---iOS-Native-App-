MokoApp.swift is the @main entry point: it pre-warms MokoFlossLoadingView, applies global UISegmentedControl tinting, and registers all SwiftData models (OnboardingState, OnboardingQuestion, OnboardingResponse, Profile, CalmDownModel, Quest, InsightsModel) in a single modelContainer. ContentView owns an AppScreen enum state machine that routes between splash → intro/auth → onboarding info → onboarding questions → reflection → microphone permission → home, persisting Profile/OnboardingState/OnboardingQuestion/OnboardingResponse/InsightsModel through @Environment(\.modelContext). The home tab is rendered by MokoRootView from the home_screens child; shared features (AFM debriefs, animation/audio playback, quest library) are imported as sibling modules and consumed by the feature screen children. Cross-cutting infrastructure at this level — SupabaseManager, AuthService, GoogleAuthService, and the delete-account Edge Function under supabase/functions — is used by both start_screens (auth flow) and home_screens (profile/account operations), keeping cloud concerns out of individual feature screens.
