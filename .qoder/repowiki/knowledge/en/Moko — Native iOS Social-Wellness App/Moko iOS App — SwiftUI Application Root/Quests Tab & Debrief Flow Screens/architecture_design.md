Five SwiftUI views form a linear flow: `QuestsScreen` (list grouped by day with filter chips) → `QuestDetailScreen` (briefing + slide-to-debrief) → `QuestDebriefScreen` (conversation coach). Cross-cutting concerns live in `Mokonavigation.swift`, which defines `OverviewMode`/`SessionEndReason` enums, two `EnvironmentKey`-backed environment values (`openOverview`, `endSession`) used to navigate back into the app's root tab, and `PendingDebriefStore` (UserDefaults-backed) for resuming an unfinished debrief. Data is owned by SwiftData models (`Quest`, `Profile`) accessed via `@Query`/`modelContext`; persistence mutations go through shared helpers like `QuestProgress.complete` and `QuestProgress.saveDebrief`. The debrief AI layer is abstracted behind the `DebriefCoaching` protocol with `DummyDebriefCoach` as fallback and `AFMDebriefCoach` selected at runtime when `AFM.isAvailable`; similarly, brief generation uses the `QuestBriefGenerating` protocol with `AFMQuestBriefGenerator` / `DummyQuestBriefGenerator`. Navigation between list/detail/debrief uses a combination of `NavigationStack`, `.navigationDestination(item:)`, and `.fullScreenCover(item:)` driven by local `@State` route enums rather than global routing.
