Pure SQL backend with no application code: versioned migrations under `migrations/` define three public tables (`quest_library`, `imagery_guides`, `imagery_guide_tags`, plus a single-row `imagery_guide_screen_content`) that the iOS app reads exclusively. Each migration enables Row Level Security policies granting `select` to `anon`/`authenticated` filtered by `is_active = true`, revokes write access, and ends with `notify pgrst, 'reload schema'` so PostgREST picks up changes immediately. Artwork lives in two Supabase Storage buckets (`quest-library`, `imagery-guide`) referenced by `image_url`/`audio_url` columns; source images are kept in `imagery-guide/` for upload but not bundled into the app. Seed files (`seed.sql`, `imagery_guides_seed.sql`) are idempotent and link uploaded assets back to rows. The `.temp/cli-latest` and `.temp/linked-project.json` files are local Supabase CLI cache artifacts.
