The repo is a single `PBXFileSystemSynchronizedRootGroup` target (`Moko/Moko.xcodeproj`, root `Moko/Moko/`) whose compiled Swift sources are auto-included; sibling directories (`Moko/Features/`, `Moko/RiveProjects/`, `Moko/.agents/`) are NOT part of the build. Runtime wiring: `ios_app` provides the SwiftUI shell and `ContentView` state machine (splash → auth → onboarding → home) in `Moko/Moko/`; it consumes `supabase_backend` for read-only Explore/Imagery data via `SupabaseManager.shared.client` plus a Deno edge function at `Moko/Moko/supabase/functions/delete-account/`; it renders `rive_projects` (.riv assets under `Resources/Animations/`) through `RiveRuntime` alongside legacy Lottie JSONs; and it delegates language generation to the on-device AFM layer (`Features/AFM/`) which wraps every call with a static Swift fallback so the UI never blocks when Apple Intelligence is unavailable. Secrets are intended to come from `Secrets.example.xcconfig` → `Config/Secrets.xcconfig`, but the pbxproj has no xcconfig reference, so keys remain hardcoded in source as a known pitfall.
