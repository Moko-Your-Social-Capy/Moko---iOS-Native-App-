The repo is a single Xcode target (`Moko/Moko.xcodeproj`, `PBXFileSystemSynchronizedRootGroup` rooted at `Moko/Moko/`) whose compiled Swift sources are auto-included; sibling directories like `Moko/Features/`, `Moko/RiveProjects/`, and `Moko/.agents/skills/rive-animation/` are NOT part of the build. The runtime wiring is: `ios_app` provides the SwiftUI shell and state machine in `Moko/Moko/`; it consumes `supabase_backend` for read-only Explore/Imagery data via `SupabaseManager.shared.client` (URL/anon key) plus a Deno edge function for account deletion; it renders `rive_projects` (.riv assets) through `RiveRuntime` alongside legacy Lottie JSONs; and it delegates language generation to the on-device AFM layer (`Features/AFM/`) which wraps every call with a static Swift fallback so the app never blocks when Apple Intelligence is unavailable. Secrets are intended to come from `Secrets.example.xcconfig` → `Config/Secrets.xcconfig`, but the pbxproj currently has no xcconfig reference, so keys remain hardcoded in source as a known pitfall.
