MokoApp.swift is the @main entry point: it pre-warms MokoFlossLoadingView, applies global UISegmentedControl tinting, and registers all SwiftData models (OnboardingState, OnboardingQuestion, OnboardingResponse, Profile, CalmDownModel, Quest, InsightsModel) via a single modelContainer. ContentView owns an AppScreen enum state machine that routes between splash → intro/auth → onboarding info → onboarding questions → reflection → microphone permission → home, persisting Profile/OnboardingState/OnboardingQuestion/OnboardingResponse/InsightsModel through modelContext during onboarding. The home tab is rendered by MokoRootView (from the home_screens child), while shared features (AFM, animation, audio, quest library) are imported as modules and consumed by the feature screen children. Supabase integration (SupabaseManager, AuthService, GoogleAuthService) and the delete-account Edge Function live at this level as cross-cutting infrastructure used by start_screens and home_screens.
